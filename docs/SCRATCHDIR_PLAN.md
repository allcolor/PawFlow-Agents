# ScratchDir — Managed Ephemeral Filesystem Plan

Status: **proposed, implementation-ready; no implementation yet**

Scope: a managed, bounded, expiring filesystem for one conversation agent, used
instead of `/tmp`, repository-local hidden directories, or ad-hoc working
directories for agent-visible temporary work.

Primary user outcome: every agent has one official place for intermediate files,
build products, package runtime state, downloaded inputs, generated reports, and
resume artifacts without polluting the project workspace or inventing paths.

## 1. Definition

ScratchDir is the filesystem counterpart of Scratchpad.

| System | Stores | Scope | Lifetime | Automatic context |
|---|---|---|---|---|
| Scratchpad | Small text notes | user × conversation × agent | Expiring | Topic/count hint only |
| ScratchDir | Files and directory trees | user × conversation × agent | Expiring | Availability/usage hint only |

The relay identity is part of the internal storage key because bytes physically
exist on one relay. It is not a user-selected scope and is never accepted from
the model as a path component.

ScratchDir is not:

- the operating-system temporary directory;
- a hidden directory inside the user's repository;
- FileStore;
- a Git worktree;
- a provider session home;
- durable memory;
- a hostile-code sandbox.

## 2. Decisions

1. The canonical filesystem selector is `scratchdir`.
2. Filesystem tools accept `source="scratchdir"`,
   `destination="scratchdir"`, or `filesystem="scratchdir"` as appropriate.
3. The canonical URL is `fs://scratchdir/<relative-path>`.
4. Executed processes see the exact scoped root at `/scratch`.
5. Physical paths are generated by the relay and never shown to or supplied by
   the model.
6. Scope is derived from authenticated tool context:
   `(user_id, conversation_id, agent_name, relay_id)`.
7. There is one root per scope. Consumers use owned subdirectories such as
   `pfp/`, `build/`, `downloads/`, and `reports/`.
8. ScratchDir survives turns, context compaction, provider cold starts, server
   restarts, and relay reconnects until expiry or explicit clearing.
9. The default TTL is seven days and the maximum TTL is thirty days, matching
   Scratchpad's current 168-hour and 720-hour limits.
10. Expiry is explicit. Ordinary reads do not renew it. `ensure` and `renew`
    set a new expiry.
11. Capacity and availability failures are fail-closed. PawFlow never falls back
    to `/tmp`, the repository root, a provider home, or FileStore.
12. ScratchDir contents are never injected into an LLM prompt. Context contains
    only a compact availability, expiry, file-count, and byte-usage hint.
13. Final deliverables move to FileStore or the project explicitly. ScratchDir
    is never silently promoted to durable storage.
14. ScratchDir and Git worktree isolation compose: the worktree contains source
    changes; ScratchDir contains disposable task artifacts.
15. Shared delegates have their own agent-scoped roots. Spawned tasks naturally
    get distinct roots because their task conversation IDs are distinct.

## 3. Why this is required

PawFlow currently has no canonical temporary filesystem for agent workflows.
Code consequently creates paths wherever execution happens.

The concrete defect found on 2026-08-21 is the PFP relay runtime:

- `core/pfp_runtime/_bridge.py:_relay_package_root()` returns
  `.pawflow/pfp/packages/<package>@<version>-<digest>`;
- the runtime writes its runner, SDK, request envelopes, FlowFile staging, and
  artifacts below that repository-relative root;
- a Pixazo invocation therefore left
  `.pawflow/pfp/packages/pawflow.pixazo-provider@...` in the project;
- the residue had to be deleted and `/.pawflow/` added to `.gitignore`.

Ignoring the residue prevents Git noise but does not solve ownership, expiry,
quota, cross-agent isolation, or cleanup. PFP must migrate to ScratchDir.

Other production uses of `tempfile`, `/tmp`, and hidden workspace
directories must be audited. The migration is semantic, not a blind textual
replacement:

- agent-visible, resumable, relay-executed, or long-running intermediate files
  belong in ScratchDir;
- process-private atomic staging that is created and removed inside one bounded
  call may continue using the platform temporary API;
- tests may continue using their test framework's temporary directories.

## 4. Lifecycle

A ScratchDir record has a UUID and timestamp at creation and stores:

- owner user ID;
- conversation ID;
- agent name;
- relay ID;
- opaque relay locator;
- state: `active`, `expired`, `clearing`, `cleared`, or `orphaned`;
- fencing epoch and revision;
- created, updated, expires, cleared, and last-reconciled timestamps;
- configured file-count and byte quotas;
- observed file count and bytes;
- last operation receipt.

Lifecycle:

```text
absent
  -> ensure -> active
active
  -> renew -> active
  -> expiry -> expired
  -> clear -> clearing -> cleared
expired
  -> clear -> clearing -> cleared
  -> ensure -> active with a new epoch/root
unknown relay outcome
  -> reconcile -> active | cleared | orphaned
```

Every mutating operation is idempotent under an operation UUID. Clearing uses
the exact recorded locator, owner, and epoch. It never deletes by wildcard or
name prefix.

## 5. Management tool

Add one `scratchdir` management tool. It manages the root; ordinary filesystem
tools manage its contents.

Actions:

- `status`: availability, relay, expiry, quotas, file count, and bytes;
- `ensure`: create the scoped root if absent and return its logical URL;
- `renew`: set a validated TTL on an existing root;
- `clear`: delete the exact scoped root after ownership checks;
- `reconcile`: operator/internal recovery only, not normally model-visible.

Example:

```json
{
  "action": "ensure",
  "ttl_hours": 168
}
```

Result:

```json
{
  "format": "pawflow.scratchdir.v1",
  "status": "active",
  "url": "fs://scratchdir/",
  "mount_path": "/scratch",
  "expires_at": "2026-08-28T12:00:00Z",
  "quota_bytes": 1073741824,
  "quota_files": 10000
}
```

No action accepts `user_id`, `conversation_id`, `agent_name`,
`relay_id`, a physical root, or a locator from the model.

## 6. Filesystem routing

Extend `BaseFsHandler` and its helpers with a reserved `scratchdir` service.
It is resolved before ordinary relay service lookup.

Required behavior:

- `fs://scratchdir/a/b.txt` parses as service `scratchdir` and relative path
  `a/b.txt`;
- absolute paths, `..`, empty path components, and symlink escapes are denied;
- read, write, edit, patch, copy, move, delete, glob, grep/search, and directory
  listing use the same scoped route;
- `bash`, `run_tests`, `security_scan`, and composite relay tools can set
  their working directory to `fs://scratchdir/<subdir>`;
- an explicit ordinary relay ID cannot bypass ScratchDir scope;
- `local=true` cannot reinterpret a ScratchDir URL against the host;
- checkpoints and project graph/wiki refresh are disabled for ScratchDir writes;
- read-before-edit remains agent-scoped and therefore still applies;
- copy is explicit across ScratchDir, FileStore, and workspace boundaries.

The model sees logical paths only. Tool results never disclose the relay's
physical runtime path.

## 7. Relay storage

Add a `scratchdir_v1` relay capability and control-plane RPCs:

- `scratchdir_ensure`;
- `scratchdir_status`;
- `scratchdir_renew`;
- `scratchdir_clear`;
- `scratchdir_reconcile`;
- scoped filesystem and exec routing using the returned opaque locator.

The relay owns the byte directory outside its configured workspace root and
inside persistent managed runtime state. Native Relay, Relay Desktop, managed
server relay, and PawCode relay must map this state to a persistent volume.
Container `/tmp` is not an acceptable backing store.

Suggested physical shape is implementation-private:

```text
<relay-runtime>/scratchdirs/<opaque-scope-uuid>/
```

The name is not derived from raw user, conversation, or agent text. A sidecar
record binds the opaque directory to its owner, epoch, quotas, and expiry.

Repository-relative `.scratch`, `.pawflow`, `.work`, and similar
directories are forbidden as ScratchDir backing paths.

## 8. Server metadata

Add `core/scratchdir_store.py` with SQLite metadata under
`data/runtime/scratchdirs/scratchdirs.sqlite3`, and add
`SCRATCHDIRS_DIR` to `core/paths.py`.

The server store is the source of orchestration state; the relay is the source
of byte and usage truth. Both sides keep operation receipts so disconnects are
reconciled before retry.

All required identifiers are explicit. Missing user, conversation, agent, relay,
or capability raises a typed error. There is no anonymous or default scratch
scope.

## 9. Quotas and cleanup

Installation seeds explicit operator settings. Initial recommended values:

- 1 GiB and 10,000 files per scope;
- 5 GiB across active scopes per user and relay;
- seven-day default TTL;
- thirty-day maximum TTL;
- one-hour cleanup sweep;
- bounded status and directory-list output.

The relay enforces quotas before and during writes. A failed write must not leave
a partially accepted file reported as complete.

Expiry fences new writes immediately. Cleanup is asynchronous and exact. A
failed cleanup becomes `orphaned` or `cleanup_blocked` and remains visible to
operators; PawFlow does not broaden deletion.

Conversation deletion, agent removal, and explicit `scratchdir clear` schedule
cleanup. Force-stop does not synchronously erase the root: useful artifacts
remain until normal TTL or explicit clearing.

## 10. PFP migration

PFP is the first mandatory consumer.

Replace the repository-relative package root with scoped directories:

```text
fs://scratchdir/pfp/packages/<package-cache-key>/
fs://scratchdir/pfp/runs/<invocation-uuid>/
fs://scratchdir/pfp/runs/<invocation-uuid>/inputs/
fs://scratchdir/pfp/runs/<invocation-uuid>/outputs/
```

Rules:

1. Ensure ScratchDir before deploying or executing a PFP.
2. Cache immutable package bytes by signed package hash beneath `pfp/packages`.
3. Put request envelopes, FlowFile staging, runtime output, and logs in a unique
   invocation directory.
4. Run the entrypoint with that invocation directory as its working directory.
5. Copy declared final artifacts to their explicit destination.
6. Remove successful invocation directories promptly; retain failed runs under a
   short diagnostic TTL.
7. Never write `.pawflow` into the project workspace.
8. If `scratchdir_v1` is unavailable, return
   `scratchdir_unavailable`; do not execute from the project root.

This migration removes the cause of the Pixazo residue rather than relying on
`.gitignore`.

## 11. Additional migration audit

Audit production code and classify each occurrence of:

- `tempfile.NamedTemporaryFile`;
- `tempfile.TemporaryDirectory`;
- `tempfile.mkdtemp`;
- literal `/tmp`;
- repository-local hidden working directories;
- generated outputs written to the current working directory.

Prioritize:

1. PFP relay runtime and FlowFile staging;
2. long-running/background tool output;
3. build, Ruff, test, security-scan, and packaging artifacts initiated by agents;
4. browser/media download and conversion intermediates;
5. relay login/configuration handoffs that must survive async boundaries.

Do not migrate safe single-call implementation details merely to eliminate the
word `tempfile`. The acceptance question is whether an agent may need to name,
reuse, inspect, resume, or clean the file across calls.

## 12. Scratchpad and context behavior

Scratchpad and ScratchDir remain separate tools because their retrieval and
storage models differ.

The agent context may contain only:

```text
ScratchDir: available on <relay-label>, 14 files / 28 MiB, expires in 5d.
Use fs://scratchdir/ for temporary files; do not use /tmp or project-local
hidden directories for resumable work.
```

File names and contents are pull-only. The hint is omitted when the relay is not
available, except when an active root is known but disconnected; that state is
reported explicitly.

The tool-selection guide routes:

- temporary text evidence and hypotheses -> Scratchpad;
- temporary files and directory trees -> ScratchDir;
- unfinished work state -> TodoList;
- user deliverables and attachments -> FileStore;
- source changes -> workspace or leased Git worktree;
- durable facts -> Memory/Knowledge Graph/Diary as appropriate.

## 13. Relationship with Git worktree isolation

`docs/GIT_WORKTREE_ISOLATION_PLAN.md` remains authoritative for parallel source
editing. ScratchDir is a prerequisite-level filesystem primitive, not a
replacement.

For a spawned coding task:

```text
/workspace  -> task's leased Git worktree
/scratch    -> task conversation/agent ScratchDir
/filestore  -> explicit durable/user-facing files
```

The worktree lifecycle never deletes ScratchDir implicitly. Candidate sealing
must ignore ScratchDir because it is physically outside the Git repository.
Validation commands may use ScratchDir for caches and reports while running
against the worktree.

## 14. Security invariants

1. Every record and operation has a UUID and creation timestamp.
2. Scope comes from authenticated execution context, never model arguments.
3. Cross-user, cross-conversation, cross-agent, and cross-relay access is denied.
4. All path resolution is containment-checked after symlink resolution.
5. Special files, device nodes, sockets, and unsafe links are rejected.
6. Physical paths and opaque locators are not returned to the model.
7. `local=true`, explicit relay IDs, aliases, and absolute paths cannot bypass
   the scoped root.
8. Secrets are not copied into logs, metadata, or context hints.
9. Clearing checks exact ownership and epoch before deleting.
10. Relay disconnects produce an unknown outcome that is reconciled before retry.
11. ScratchDir provides collision and scope isolation, not malicious-code
    containment.
12. No unavailable-capability path silently writes elsewhere.

## 15. UI and operations

Add a ScratchDir section beside Scratchpad in the cognitive/resources UI.

Show:

- selected agent and relay;
- active/disconnected/expired/orphaned status;
- usage, quotas, and expiry;
- bounded file tree;
- renew and clear actions;
- copy selected file to FileStore;
- open/download through existing authorized file routes.

All dialogs must have a close button, an X, and Escape handling.

Operator diagnostics show scope UUID, relay, state, usage, and receipts. Physical
paths require an explicit privileged relay-local diagnostic action.

## 16. Failure taxonomy

Use stable codes:

- `scratchdir_context_missing`;
- `scratchdir_relay_required`;
- `scratchdir_capability_missing`;
- `scratchdir_unavailable`;
- `scratchdir_not_found`;
- `scratchdir_expired`;
- `scratchdir_epoch_stale`;
- `scratchdir_owner_mismatch`;
- `scratchdir_path_escape`;
- `scratchdir_quota_bytes`;
- `scratchdir_quota_files`;
- `scratchdir_read_only`;
- `scratchdir_outcome_unknown`;
- `scratchdir_cleanup_blocked`;
- `scratchdir_orphaned`.

Messages explain remediation and never blame the OS, cache, library, or relay.

## 17. Test plan

Unit tests:

- required scope and UUID/timestamp creation;
- TTL bounds and explicit renewal;
- state transitions and compare-and-swap revisions;
- alias and URL parsing;
- logical relative path normalization;
- quota accounting;
- context hint construction;
- tool schema and error rendering.

Relay integration tests:

- ensure creates one exact managed root outside the repository;
- restart and reconnect retain it;
- two users, conversations, agents, and relays receive isolated roots;
- relative, absolute, symlink, and `..` escapes fail;
- stale epochs cannot write;
- byte and file quotas are enforced;
- exact clear cannot remove neighboring roots;
- unknown ensure/clear outcomes reconcile idempotently;
- no relay capability fails closed.

Filesystem contract tests:

- read/write/edit/patch/copy/move/delete/glob/search work through
  `fs://scratchdir/`;
- `source=scratchdir` and the URL are equivalent;
- `bash` sees the same root at `/scratch`;
- `local=true` and explicit relay IDs cannot escape;
- project graph/wiki refresh and Git checkpoints do not run for scratch files.

PFP tests:

- no invocation creates `.pawflow` in the project;
- package cache and run directories live in ScratchDir;
- successful runs clean their invocation directory;
- failed runs remain inspectable until expiry;
- artifacts and FlowFiles cross boundaries only through explicit copy;
- missing ScratchDir capability prevents execution with a typed error.

End-to-end acceptance:

1. An agent creates files with `fs://scratchdir/`, restarts, and reads them.
2. Another agent in the same conversation cannot see them.
3. A spawned task uses its own ScratchDir while editing its own worktree.
4. A PFP invocation leaves the repository byte-for-byte clean.
5. Quota and expiry failures never spill into `/tmp` or the repository.
6. A user copies one result to FileStore and clears the remaining root.
7. Server and relay restart during create/write/clear yield one reconciled result.

## 20. Release gates

ScratchDir is complete only when:

1. every handler, state transition, relay RPC, and UI action has unit coverage;
2. native and containerized relay persistence is tested;
3. scope isolation and path-bypass tests pass;
4. quota, expiry, cleanup, disconnect, and restart tests pass;
5. PFP never creates repository-local runtime state;
6. required consumers fail closed when ScratchDir is unavailable;
7. no automatic fallback targets `/tmp`, the workspace, provider home, or
   FileStore;
8. all filesystem and execution tools use the same logical root;
9. full pytest, Ruff, Bandit, packaging, and relevant platform CI pass;
10. docs and public status distinguish ScratchDir from Scratchpad, FileStore, and
    Git worktrees;
11. a manual test demonstrates create, reuse after restart, PFP execution,
    FileStore promotion, expiry, and exact cleanup.

## 21. Final position

ScratchDir is a first-class scoped storage primitive:

```text
Scratchpad -> temporary text
ScratchDir -> temporary files
FileStore  -> durable/user-facing files
Workspace  -> project source
Worktree   -> isolated project source for one spawned coding task
```

When an agent needs a temporary file that may outlive one process call, the
answer is always `fs://scratchdir/`. It must never invent `/tmp/foo`,
`.pawflow/`, `.scratch/`, or another repository-local working directory.
