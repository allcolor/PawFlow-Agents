FAQ

Answers before the install.

The short version: PawFlow is a self-hosted runtime for agents, relays, shared context, media tools, and deterministic flow automation.

Is PawFlow a hosted agent cloud?

No. PawFlow is designed to be self-hosted. You run the server and decide which LLM providers, relays, workspaces, secrets, and media services are connected.

What leaves my machine?

It depends on provider and tool configuration. Prompts and selected context go to the chosen LLM provider. Relay tool requests cross from PawFlow to the relay. Media prompts and source media may go to configured media providers. Your deployment controls those boundaries.

Can I encrypt conversations at rest?

Yes, opt-in per conversation. Enable it with /encrypt on and a passphrase: message content, thinking, and tool arguments/results are stored as ciphertext on disk while metadata stays clear so the store keeps working. The key lives in server RAM only — logout, 15-minute idle, or a server restart re-locks it, so a stopped server leaves only ciphertext. Optional recovery passphrase and trusted key-relay (auto-unlock) are supported. There is no recovery without one of those, so store the passphrase safely. Conv-scoped relay workspaces can also be encrypted with CryFS via /relay encrypt. Conversations without encryption are completely unchanged.

Why use a relay?

The relay lets agents work next to a filesystem, shell, browser, desktop, or local service without giving the PawFlow server permanent direct filesystem access. It is the main boundary between orchestration and execution.

What is the difference between a server relay and a remote relay?

A server relay is a full relay that runs on the PawFlow server itself, with the same filesystem, shell, browser, and tool surfaces as any other relay. It is the pure remote self-hosted setup: agents (and you) work directly in server-side workspaces, no extra machine needed. A remote relay is the client installed on the machine that owns the workspace or desktop, using Relay Desktop for a GUI install or Relay CLI for terminal/server machines.

Can agents use a full desktop?

Yes. With Desktop Relay, agents can inspect and operate a full desktop through screen, browser, and VNC-style tools. If the relay is started with `allow_local`, the accessible desktop can be the local desktop where that relay runs; otherwise the boundary is the relay container or configured remote desktop.

Can I open terminals from webchat?

Yes. The webchat workspace menu can expose terminals for the remote Docker relay workspace, the local host surface when `allow_local` is enabled, and the server relay workspace for working directly on the PawFlow server. Keep those surfaces separate so operators know whether commands run in Docker, on the host, or on the server.

What are the context and memory editors?

The context editor lets an operator inspect and adjust the short-term context sent to the selected agent. The memory editor is for durable long-term memory: review, correct, delete, and audit remembered facts before they influence future turns.

How do interactive CLI providers run?

Subscription-backed interactive providers such as Claude Code interactive, Codex interactive, and Antigravity/Agy run through observable CLI sessions, including tmux-backed runtime state. This makes login, approvals, streaming, and provider-side issues inspectable from the relay/webchat tooling.

Where does VS Code/code-server fit?

The webchat can open VS Code/code-server against a linked relay workspace, so a human can inspect diffs, edit files, and run manual review while agents continue using the same relay-backed filesystem and tools.

Which LLM providers work?

PawFlow supports direct HTTP providers such as OpenAI, Anthropic, and OpenAI-compatible endpoints, plus CLI-backed coding agents including Codex interactive, Claude Code interactive, Antigravity/Agy, and Gemini CLI. Use the interactive providers for new Codex and Claude Code agent services. Codex app-server and Claude Code `cc -p` are legacy transports retained for existing configurations only. Use Agy as the default Gemini subscription path; use Gemini CLI for Gemini Pro or CLI-specific workflows.

Can I talk to my agents from Telegram?

Yes. Telegram is a first-class client for the shared agent runtime. Add a telegramBot service with a BotFather token, deploy the Telegram agent flow (telegramReceiver + telegramAgentClient, plus telegramConversationBridge for live event mirroring), and link your Telegram account to a PawFlow user. You then reach the same conversations, agents, multi-agent context, attachments, and FileStore outputs as web chat, with text, documents, photos, voice, and slash commands. See the Telegram how-to.

Can I embed a PawFlow agent in my own application?

Yes, three ways from one publish action. MCP exposes a conversation's tools and context to MCP clients. A2A 1.0 exposes the agent to other agent runtimes. AG-UI brings the agent into user-facing apps: any AG-UI client (CopilotKit and the wider ecosystem) posts a RunAgentInput to /agui/{publication_id} with the publication's Bearer key and reads back a streaming SSE run — including frontend tools your app executes, a shared state document synchronized live, and interrupts your UI answers. See the AG-UI how-to.

Can I use several providers in one conversation?

Yes. Agents reference LLM services by id, so different agents in the same conversation can use different providers, models, credentials, permissions, and tool sets.

What is the difference between an agent and a flow?

An agent is useful for exploration, coding, reasoning, tool use, and maintenance. A flow is an explicit task graph for repeatable execution: triggers, routing, transforms, retries, checkpoints, and LLM calls only where modeled.

When is execution deterministic?

Flow execution is deterministic where it uses explicit tasks and fixed inputs. Any `inferLLM` or agent task remains intentionally model-driven, so you choose where variability is allowed.

Can agents edit my files?

Only through configured tools and relays. Use narrow permissions, approval gates, Docker relays for untrusted work, and read-only inspection before allowing edits, shell commands, deletes, or desktop control.

Can PawFlow generate media?

Yes. Agents can use provider-backed image, video, audio, voice, 3D, try-on, lipsync, and upscaling tools. Outputs should be stored as FileStore URLs or real files, not embedded as base64 in conversation text.

How do I enable TTS and STT?

Add a TTS service such as Supertonic, Voicebox, LuxTTS, or a compatible hosted provider, then add an STT service such as OpenAI-compatible STT or Voicebox. The webchat speaker and microphone controls use those services, and agents can also call voice tools such as `speak`, `clone_voice`, and `speech_to_video` when configured.

Can I talk to an agent live, like a phone call?

Yes. Add a realtimeVoiceConnection service (OpenAI Realtime with a gpt-realtime model, or Gemini Live with a gemini connection that has an api_key) and click the microphone button in the webchat. You get a full-duplex spoken conversation with live captions, barge-in, optional push-to-talk, spoken tool use, and transcripts saved as normal conversation history. Agents pinned to a voice service also answer Telegram voice notes with voice notes. See the realtime voice how-to.

Can I run PawFlow on a VPS?

Yes. Use the Docker install path, persistent volumes, HTTPS or a reverse proxy, strong secrets, the Private Gateway for exposed demos, and restrictive relay/tool permissions.

Is PawFlow production-ready?

It is beta software with a substantial runtime, docs, tests, and deployment path. Treat internet-facing deployments carefully: use production env settings, HTTPS, strong secrets, restricted tools, budget caps, and reviewed OAuth redirects.

How do I update a Docker install?

From the browser: Admin → Update server pulls the release and recreates the server container from a throw-away pawflow-updater container, keeping bind-mounted persistent data. The page waits for a different server process to answer /health before reloading, so a failed update reports the failure and points at docker logs pawflow-updater instead of looking finished. From the command line: bash scripts/install-pawflow.sh --check-updates, then --version NEW_VERSION --port PORT --pull-images. Do not delete ~/pawflow data unless you explicitly want a fresh install. See the update how-to.

What permissions does a new conversation start with?

New conversations are created in auto permission mode: the tools the mode allows run without prompting. Conversations created before this default keep the mode they were running under. Change it per conversation from the permission selector in the web chat — use default or read_only when agents work against production systems or untrusted input. See the security model.

When I approve a tool call, what exactly am I approving?

The call that runs. Arguments are decoded and wrapper tool names are resolved to the inner tool before the dialog is built, so the dangerous-command scan reads the real command rather than an empty payload. Tool names that execute as bash — shell, exec, run and friends — are classified as bash for approval. If a conversation hook or variable resolution changes the call after you approved it, it is re-authorized; an unchanged call never prompts twice. See the security model.
